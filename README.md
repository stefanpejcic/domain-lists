### API

`/api/v1` lists available endpoints. Unlike the browser download flow (which
gates files behind a captcha/countdown and single-use tokens), the API is
meant for scripts: no token dance, just a 60 requests/minute per-IP limit.

- `GET /api/v1/summary` — global totals
- `GET /api/v1/tlds` (or `?format=csv`) — stats for every TLD
- `GET /api/v1/tld/<tld>` — stats for one TLD
- `GET /api/v1/tld/<tld>/<kind>` — direct `.txt.gz` download (`kind` is
  `domains`, `new`, or `deleted`; `tld=all` combines every TLD)

### Trending keyword lists

`/trending` and `/trending/<keyword>` browse domains registered today that
match a tracked keyword (e.g. "ai", "crypto"). Generated by
`scripts/generate_keyword_lists.py`, which filters `lists/<date>/new/all.txt.gz`
by substring match against the domain name with its TLD stripped off (so
`.ai` domains don't auto-match "ai"). It's a discovery tool, not a precision
filter — expect some false positives (e.g. "domain" contains "ai"). Run it
after `process_zones.py`; edit `keywords.json` at the repo root to change
which keywords are tracked, no code changes needed.

### Threat matches

`/threats` and `/threats/<source>` browse domains registered today that are
already flagged by a threat intel source (OpenPhish, URLhaus, or Google Safe
Browsing). Generated by `scripts/generate_threat_matches.py`, run after
`process_zones.py`:

- **OpenPhish / URLhaus** (free, public, no API key) — each feed entry is a
  full URL; we extract its hostname and walk its dot-suffixes
  (`evil.sub.example.co.uk` → `example.co.uk` → `co.uk`...) against today's
  `new/all.txt.gz` domain set, taking the first hit. No public-suffix-list
  needed, since a match only counts if the exact suffix is itself a domain
  we tracked as newly registered.
- **Google Safe Browsing** (needs `G_API_KEY` in `website/.env` — the source
  is skipped entirely if unset) — unlike the feeds above, we submit our own
  domains *to* Google via its `threatMatches:find` API (batched, up to 500
  URLs/request, its documented limit), so matches are exact rather than
  suffix-derived, and it checks the full `new/all.txt.gz` set rather than a
  scoped subset.

Results are leads to investigate, not verified verdicts — all three sources
can have false positives.

### Failure alerts

`cron.sh` checks the exit code of `download_zones.py` and `process_zones.py`
and, on failure, calls `scripts/notify.py` to email the tail of the relevant
log via the local `sendmail`. The recipient is read from `EMAIL` in
`website/.env` (falls back to `stefan@pejcic.rs` if unset).

All paths in `scripts/` and `website/app.py` are resolved relative to the
repo root, so the app works regardless of where it's installed/cloned.

### Created at runtime (gitignored)

These are generated by the scripts/cron job and are not tracked in git:

```
downloads/            # raw zone files, downloaded daily (removed after processing)
lists/<date>/...      # generated domains / new / deleted / keywords / threats lists per TLD
json/...              # per-TLD stats, summary.json, pattern_counters.json, keywords.json, threats.json
venv/                  # Python virtualenv, created by install.sh
*_log.txt              # script run logs (icann_download_log.txt, zone_processing_log.txt, ...)
sitemap.xml             # written by scripts/generate_sitemap.py
website/static/css/style.css  # written by scripts/build_css.sh
website/static/og/            # written by scripts/generate_og_images.py
```
